Knowledge Graph-Enhanced RAG (KG-RAG)

Module 2 — Technical Architecture Lesson 4 of 13 Source: arxiv.org/abs/2311.17696
Primary Source
"How to Build an Adaptive AI Tutor for Any Course Using KG-RAG" ICEIT 2025 — arxiv.org/abs/2311.17696
n = 76 students · KG-RAG group scored +35% higher on assessments (p < 0.001)

The Problem with Standard RAG

Retrieval-Augmented Generation (RAG) improves factual grounding by pulling relevant passages from a document store before the LLM generates its response. In most settings this works well — but tutoring exposes a structural flaw.

Standard RAG ranks candidates by semantic similarity: the retrieved passage is whatever sits closest to the query in embedding space. That is fine when the goal is information lookup. It is not fine when the goal is teaching, because conceptual proximity and pedagogical prerequisite order are not the same thing.

The silent failure mode
A student asking about gradient descent might receive a passage about neural networks — semantically close, but pedagogically wrong. What they actually need is a prerequisite explanation of derivatives. Standard RAG has no way to know this, because it does not represent the dependency structure of the domain.

The retriever finds text that is near the query. It does not ask: what does a student need to understand before this concept makes sense? Without that question, an AI tutor can confidently explain things in the wrong order — each sentence individually correct, yet the sequence pedagogically incoherent.

What a Knowledge Graph Adds

A knowledge graph (KG) encodes the explicit conceptual relationships that a curriculum designer would draw on a whiteboard. Rather than a flat bag of documents, the KG is a structured network of concept nodes connected by typed edges:

  • gradient descent requires derivatives
  • backpropagation uses chain rule
  • chain rule requires partial derivatives
  • neural networks relates to optimization
Key insight — the KG as conceptual anchor
The knowledge graph anchors retrieval to the domain’s dependency structure. It does not replace the LLM’s generative ability — it constrains what gets retrieved so that explanations are logically sequenced before they reach the model. The graph is the curriculum made machine-readable.

Without this anchor, retrieved context is determined by surface similarity alone. The KG makes the prerequisite chain visible to the retrieval step, so the system can surface foundational concepts even when the student’s query does not mention them.

The KG-RAG Pipeline

At its core, KG-RAG adds a graph traversal step between the student’s query and the LLM’s response. The simplified pipeline has four stages:


  Student question
        │
        ▼
  ┌─────────────────────────────────────────┐
  │  1. CONCEPT MATCHING                    │
  │     Query → matched concept node in KG  │
  └──────────────────┬──────────────────────┘
                     │
                     ▼
  ┌─────────────────────────────────────────┐
  │  2. GRAPH TRAVERSAL                     │
  │     Walk neighbor nodes:                │
  │     • prerequisite concepts             │
  │     • related concepts                  │
  └──────────────────┬──────────────────────┘
                     │
                     ▼
  ┌─────────────────────────────────────────┐
  │  3. DOCUMENT RETRIEVAL                  │
  │     Fetch source passages attached      │
  │     to each node in the traversal set   │
  └──────────────────┬──────────────────────┘
                     │
                     ▼
  ┌─────────────────────────────────────────┐
  │  4. GROUNDED GENERATION                 │
  │     LLM generates an answer using the   │
  │     retrieved context + student model   │
  └─────────────────────────────────────────┘
        │
        ▼
  Response to student

The key difference from standard RAG is step 2. The graph traversal means the retrieval set is not just what is closest to the query but what the curriculum says the student needs to understand this concept. Prerequisites travel with the target — the LLM sees the full conceptual context, not just the nearest embedding neighbors.

What the LLM receives

By the time the language model generates a response, it has been given:

  1. The student’s original question.
  2. Passages covering the target concept.
  3. Passages covering prerequisite concepts (surfaced by graph traversal).
  4. Awareness — through the student model — of what the student should already know.

This allows the model to pitch its explanation at the right level and in the right order, rather than guessing from the query alone.

The Evidence: n = 76, +35%

The ICEIT 2025 paper ran a controlled comparison between two groups of 76 students: one tutored by a standard LLM system, one tutored by a KG-RAG system drawing on the same underlying course material.

The KG-RAG group scored 35% higher on assessments (p < 0.001). The researchers attributed the gain to two properties of the KG-RAG design:

  • Factual drift prevention. The graph constrains what the model can say about a topic. Explanations stay anchored to the course’s conceptual structure rather than drifting toward plausible-sounding but off-curriculum content.
  • Logical sequencing. Because prerequisites are retrieved alongside the target concept, the model’s explanations build on each other in the correct order rather than presenting advanced ideas before foundational ones are established.

Why This Matters Architecturally

KG-RAG is the bridge between raw LLM generation and a principled tutoring system. The diagram below shows where it sits in the broader architecture: 


  Raw LLM              KG-RAG               Full ITS
  ─────────────        ──────────────────   ──────────────────────────
  Query → LLM    →     Query → KG → LLM →  Query → Student Model
  (no retrieval)       (structured               → KG traversal
                        retrieval)               → Prerequisite retrieval
                                                 → Adaptive generation
                                                 → Reassessment loop

Without the KG layer, the system sits at the left — fluent but structurally blind. The KG adds domain structure. Subsequent components (student modeling, knowledge tracing, adaptive path planning) layer on top of this foundation. You cannot sequence explanations correctly before you have made the prerequisite relationships machine-readable.

This is also why KG-RAG is taught before knowledge tracing (Lesson 5) and multi-agent planning (Lesson 6): the KG is the shared data structure that those later components query. Get the graph wrong and everything downstream degrades.
