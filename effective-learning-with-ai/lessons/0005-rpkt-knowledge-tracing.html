Dynamic Knowledge Tracing — Finding What Students Don't Know They Don't Know

Module 2 — Technical Architecture Lesson 5 of 13
Primary Source

The Unknown Unknowns Problem

Standard curriculum design rests on a flawed assumption: that students can accurately self-report what they do and don't understand. In practice, a learner might confidently claim they know recursion while holding a fundamentally broken mental model of the call stack. They have never been shown the gap — so they cannot name it.

Quiz-based assessments only surface what the instructor thought to test. If the quiz author didn't anticipate that a student might confuse stack frames with heap allocation, the confusion goes undetected. The result is a student who progresses through material without the foundations they actually need, and an AI tutor that answers questions fluently without ever diagnosing the underlying misunderstanding.

This is the unknown unknowns problem: the knowledge gaps that matter most are precisely the ones neither the student nor a static assessment can surface.

Why Static Knowledge Graphs Fall Short

One response to the unknown unknowns problem is to build a detailed knowledge graph (KG) in advance — a map of every concept in a domain and every prerequisite relationship between them. An AI tutor can then walk this graph to identify where a student's understanding breaks down.

The problem is that hand-authored KGs are fragile in practice:

  • They go stale. Curricula evolve, new frameworks emerge, and the relationships between concepts shift. A graph authored two years ago may no longer reflect how practitioners think about a domain.
  • They miss edge cases. Human authors encode the obvious prerequisite chains but often miss the subtle conceptual dependencies that trip real students up.
  • They don't transfer. A KG painstakingly built for introductory Python is useless when you need a tutor for, say, distributed consensus protocols. You'd need a domain expert to build a new graph from scratch for every subject.

This last point is especially limiting for the ambition of general-purpose AI tutoring. If every new domain requires months of expert curation, the system cannot scale.

RPKT's Solution: Dynamic Prerequisite Extraction at Runtime

RPKT — Recursive Prerequisite Knowledge Tracing — takes a different approach. Rather than relying on a pre-built graph, it uses an LLM to generate prerequisite relationships dynamically, at the moment they are needed.

The core insight is that large language models already encode a substantial understanding of how concepts relate to one another within their training data. When a student struggles with concept X, RPKT asks the LLM: "What must a student already understand in order to grasp X?" The LLM returns a set of prerequisite concepts. RPKT then probes the student on each of those, and if a gap is found, it recurses — asking the same question about the prerequisite concept, and so on down the dependency tree.

The process terminates when the student demonstrates understanding at the bottom of a branch, or when no deeper prerequisites can be generated. What emerges is a hierarchical learning path tailored to this student, for this concept, at this moment — generated entirely at runtime with no pre-built curriculum.

How the Recursive Trace Works

RPKT walks the prerequisite dependency tree depth-first. The algorithm follows a consistent pattern at each step:

  1. Start at the target concept. The student has indicated difficulty with, or the system has detected confusion about, a specific concept.
  2. Extract prerequisites via LLM. Query the LLM for the set of concepts a student must understand before they can understand this one.
  3. Probe the student on each prerequisite. Ask a targeted question that reveals whether the student has a working understanding of each prerequisite concept — not just a surface-level definition.
  4. If a gap is found, recurse. Treat the prerequisite concept as the new target and repeat from step 2. This generates a deeper branch of the dependency tree.
  5. If no gap is found, move on. The student is solid on this prerequisite; continue checking the remaining ones at this level.

Because the trace is depth-first, RPKT follows one branch all the way to its root before backtracking. The result is a precise identification of the actual knowledge boundary — not a guess based on what the curriculum designer thought to include.

Key Design Win

RPKT requires no pre-built curriculum. Because prerequisite relationships are generated by the LLM at runtime, the system works in any domain where the LLM has sufficient training knowledge to reason about concept dependencies. This makes it tractable to build an adaptive AI tutor for arbitrary topics — without hiring domain experts to hand-author a knowledge graph for each one.

This portability is the defining advantage over static KG approaches. Deploying RPKT to a new domain — say, Byzantine fault tolerance, or financial derivatives pricing — requires no additional upfront work. The prerequisite graph is generated fresh for every student interaction.

RPKT vs. Static Knowledge Graphs

Lesson 4 covered KG-RAG: a system that uses a hand-authored knowledge graph to guide retrieval, ensuring that answers are grounded in validated, structured domain knowledge. RPKT and KG-RAG solve different problems and are designed to be complementary.

Dimension Static Knowledge Graph (KG-RAG) RPKT (Dynamic Tracing)
Graph construction Hand-authored by domain experts before deployment Generated by LLM at runtime, on demand
Primary purpose Grounding answers in validated, structured knowledge Discovering the student's actual knowledge boundary
Domain portability Low — requires expert curation per domain High — works in any domain the LLM knows well
Handles unknown unknowns? Only if the gap was anticipated in the graph Yes — recursion surfaces unanticipated gaps
Best used for Retrieving precise, trustworthy explanations Generating adaptive learning paths from a gap

In a well-designed AI tutoring system, both components earn their place: KG-RAG ensures that the content delivered is accurate and well-structured; RPKT ensures that the content delivered is the content the student actually needs.
