Multi-Agent Learning Path Planning (MALPP)

Module 2 — Technical Architecture Lesson 6 of 13
Primary Source
Multi-Agent Learning Path Planning (MALPP) arxiv.org/abs/2601.17346 — tested on the MOOCCubeX dataset across 7 LLMs; outperforms all baselines on path quality, knowledge sequence consistency, and cognitive load alignment

Why One LLM Isn't Enough for Path Planning

Generating a learning path looks, on the surface, like a single task: given a student and a target concept, produce an ordered sequence of topics. But path planning is actually three distinct problems running one after another. First, the system must analyze the learner — understanding their current knowledge state, performance history, and learning patterns. Second, it must sequence content — deciding which concepts to introduce and in what order, subject to pedagogical constraints. Third, it must reflect on the result — evaluating whether the path it generated is coherent, appropriately paced, and not cognitively overwhelming.

Bundling all three problems into a single prompt degrades each one. The diagnostics needed for learner analysis compete with the sequencing constraints for path planning. The generative posture required to produce a path conflicts with the self-critical posture required to audit it. MALPP separates these concerns into three dedicated agents — one per problem.

Three problems, three agents

Learning path generation decomposes into three distinct subproblems: analyzing the learner, sequencing content, and critiquing the result. Each requires a different cognitive stance. Assigning each to a dedicated agent outperforms bundling all three into a single prompt.

The Three MALPP Agents

Agent Input Output
Learner Analytics Agent Student's prior assessment performance, interaction history, and learning patterns A structured learner profile describing current knowledge state and identified gaps
Path Planning Agent Learner profile (from Analytics Agent) and the target concept to be mastered A sequenced learning path respecting Cognitive Load Theory and ZPD constraints
Reflection Agent The draft learning path (from Path Planning Agent) A critique identifying coherence failures or cognitive overload, plus revision requests

Learner Analytics Agent

The Learner Analytics Agent opens the pipeline. It receives the student's raw history — prior assessment scores, the topics they have engaged with, where they struggled, and how quickly they progressed — and converts this into a structured learner profile. The profile is not a summary written for human readers. It is a compact representation of the student's current knowledge state, designed to give the Path Planning Agent exactly the input it needs to make sequencing decisions.

Path Planning Agent

The Path Planning Agent takes the learner profile and the target concept and generates a sequenced path. Two constraints govern its sequencing decisions. The first is Cognitive Load Theory: working memory is limited, and a path that introduces multiple new concepts simultaneously will exceed cognitive capacity before any of them can be consolidated. The agent must sequence one new concept at a time, with interleaved practice before the next concept is introduced. The second constraint is the Zone of Proximal Development: each step must be calibrated to the student's current frontier — challenging enough to require genuine effort, not so far beyond reach that the step causes overload.

Reflection Agent

The Reflection Agent receives the draft path and subjects it to critique. It checks whether the path is globally coherent — not just whether each step follows logically from the previous one, but whether the cumulative cognitive load across the entire sequence stays within bounds. A path can be locally valid (each step is a plausible next step) while being globally overwhelming (five new concepts introduced in the first eight steps). When the Reflection Agent detects overload or an incoherent jump, it requests revisions before the path is delivered.

Cognitive Load Theory as a Hard Constraint

Cognitive Load Theory holds that working memory has a fixed capacity. When a learning task exceeds that capacity, the student cannot form the schemas needed to consolidate new information into long-term memory. The result is not partial learning — it is no durable learning at all.

For path planning, this means the number of genuinely new concepts introduced in a single step is a hard constraint, not a stylistic preference. A path that introduces HTTP, REST conventions, statelessness, authentication, and resource modeling simultaneously will exceed working memory regardless of how clearly each concept is explained. The Path Planning Agent enforces the constraint by sequencing one new concept at a time and inserting practice before advancing to the next.

The cognitive load trap

A learning path that looks reasonable on paper — topics arranged in logical dependency order — can still be cognitively catastrophic if each step introduces more than one new schema. Dependency order and cognitive load order are not the same thing.

Zone of Proximal Development in Sequencing

The Path Planning Agent does not simply order topics by prerequisite dependency. Dependency graphs tell you which concepts must precede which — they do not tell you how far the student currently is from each concept, or which next step is most within reach given the student's existing knowledge.

ZPD-aware sequencing targets each step to be at the student's learning frontier: the zone where the student does not yet grasp the concept but can reach it with effort. A step that falls below this frontier wastes time on material the student already holds. A step that exceeds it by too much causes overload and leaves no durable trace. The Path Planning Agent uses the structured learner profile from the Analytics Agent to calibrate each step to this frontier — the path is ordered not only by dependency but by reachability from where the student actually stands.

What the Ablation Study Showed

The MALPP authors removed each agent in turn from the full system and measured the resulting drop in performance. Removing any single agent degraded path quality. But the Reflection Agent's removal produced the largest degradation in cognitive load alignment across all ablation conditions.

The finding makes structural sense. The Path Planning Agent operates step by step, making locally reasonable sequencing decisions at each point. It has no mechanism to audit the cumulative load across the full path it has just produced. The Reflection Agent supplies that global view. Without it, paths were locally valid — each step followed plausibly from the previous one — but globally overwhelming, because no agent had checked whether the total number of new concepts introduced across the full sequence exceeded what a student could handle.

Ablation result

The Reflection Agent contributed the most to cognitive load alignment of any agent in the system. Its role is not optional polish — it supplies the global audit that the step-by-step Path Planning Agent is structurally unable to perform on its own.
