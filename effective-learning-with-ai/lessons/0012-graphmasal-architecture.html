What Is GraphMASAL?

GraphMASAL — Graph-based Multi-Agent System for Adaptive Learning — is currently the state of the art for AI tutoring architectures that combine knowledge graphs, multi-agent orchestration, and neural retrieval in a single integrated system. It is significant not because any one of its components is novel in isolation, but because it unifies them into a coherent pipeline and validates the combination empirically under blinded evaluation conditions.

The name carries its architecture: Graph for its dynamic knowledge graph backbone, Multi-Agent for its three specialized agents coordinated through LangGraph, and Adaptive Learning for its ability to personalize instruction path and content to each student's measured state.

GraphMASAL Synthesizes the Whole Course

GraphMASAL is not one new idea — it is the integration of every major idea in this course into a single working system. Each component introduced in Modules 1–3 reappears here in a production-grade form. The earlier lessons were not background; they were the building blocks of this architecture.

Three Core Components

GraphMASAL is built from three interlocking components. Each solves a distinct sub-problem, and together they cover the full pipeline from diagnosing a student to delivering instruction.

1. Dynamic Knowledge Graph

Unlike the static knowledge graphs covered in Lesson 4 — which are authored once and queried read-only — GraphMASAL's knowledge graph evolves as the student learns. Concept mastery states are nodes in the graph; prerequisite and co-requisite relationships between concepts are edges. As a student works through material, the system updates mastery state on nodes in real time. The graph is not a curriculum imposed on the student; it is a live model of what the student knows.

This makes the knowledge graph a shared memory structure across all three agents. The Diagnostician reads from it to identify gaps; the Planner writes path decisions to it; the Tutor reads from it to contextualize instruction. The graph is the connective tissue of the whole architecture.

2. LangGraph-Orchestrated Agents

GraphMASAL employs three specialized agents, each scoped to a distinct responsibility:

  • Diagnostician: Assesses the student's current knowledge state by probing concepts and reading the knowledge graph. It identifies gaps — concepts the student needs but has not yet mastered.
  • Planner: Takes the diagnosed gaps as input and generates a learning path: an ordered sequence of concepts that covers all gaps with minimal redundancy. It uses the multi-source multi-sink planning engine described below.
  • Tutor: Delivers instruction for each concept on the plan, drawing on retrieved learning resources. It adapts its explanations to the student's demonstrated level of understanding.

The three agents are orchestrated via LangGraph, a framework for structured multi-step conversations between agents. LangGraph enforces the sequencing — Diagnostician first, Planner second, Tutor third — and manages state between steps, ensuring each agent operates on consistent, up-to-date information from the shared knowledge graph.

3. Two-Stage Neural Information Retrieval

When the Tutor agent needs learning resources for a concept, it retrieves them through a two-stage neural IR pipeline:

  1. Dual-encoder retrieval (Stage 1): A pair of encoders — one for queries, one for documents — produces dense vector representations that enable fast approximate nearest-neighbour search across the resource corpus. This stage retrieves a broad set of candidate documents quickly via semantic similarity.
  2. Cross-encoder re-ranking (Stage 2): A single encoder processes the query and each candidate document jointly, producing a precise relevance score. The top-ranked candidates from Stage 1 are re-ordered. This stage is slower but more accurate than the dual-encoder alone.

The two stages balance competing demands: Stage 1 provides speed by searching at scale; Stage 2 provides precision by scoring candidates carefully. A single-stage system would be forced to sacrifice one for the other.

Multi-Source Multi-Sink Planning Engine

At the heart of the Planner agent is a multi-source multi-sink planning engine based on a greedy set cover approximation. The terminology captures the real structure of adaptive learning:

  • Multi-source means the path has multiple entry points — the student's current knowledge state may span several concepts at varying levels of mastery, and the plan must begin from all of them simultaneously rather than assuming a single starting point.
  • Multi-sink means the path targets multiple destination concepts — the student needs to reach a set of goals, not just one, and the plan must satisfy all of them.

Given these constraints, the Planner uses a greedy set cover approximation to construct a path that covers all identified knowledge gaps with minimum redundancy. Set cover is NP-hard in general, but the greedy approximation — always pick the next concept that covers the most uncovered gaps — performs well in practice and runs efficiently enough for real-time planning.

The result is a learning path that is both complete (no identified gap is left unaddressed) and parsimonious (the student is not walked through concepts they already understand).

Evaluation: Blinded Automated Assessment

GraphMASAL was evaluated against LLM prompting baselines — systems that prompt a language model directly to generate learning paths and instruction, without a structured knowledge graph or multi-agent pipeline. The evaluation was blinded: automated evaluators did not know which system produced which output, eliminating scoring bias toward either approach.

GraphMASAL outperformed the LLM prompting baselines on three criteria:

  1. Structural alignment of learning paths: The paths GraphMASAL produced better matched the logical prerequisite structure of the domain compared to paths generated by direct LLM prompting.
  2. Concept coverage: GraphMASAL's paths covered a higher proportion of the identified knowledge gaps without unnecessary detours.
  3. Learning cost: Students reached target concepts in fewer steps under GraphMASAL than under the prompting baselines, indicating more efficient path construction.

Expert human raters subsequently reviewed a sample of outputs and their ratings were consistent with the automated results, providing external validation that the automated metrics were measuring something real.

The blinded evaluation design is significant because it rules out a common confound in AI system evaluations: evaluators giving higher scores to outputs that feel more fluent or more elaborate, rather than to outputs that are actually better structured for learning.
