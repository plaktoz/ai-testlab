Adversarial Agent Taxonomy — Types, Roles, and the Threat Landscape

🕑 ~20 minutes Foundations
Primary Sources
  • Weng (2023), Adversarial Attacks on LLMs — a comprehensive survey cataloguing five attack categories (token manipulation, gradient-based, jailbreak prompting, human red-teaming, and model-based red-teaming) together with corresponding defenses.
  • arxiv 2312.02003 — LLM Security and Privacy Survey that organises the field into “The Good,” “The Bad,” and “The Ugly,” noting model extraction and safe instruction tuning as underdeveloped areas.
  • arxiv 2309.07864 — LLM Agents Survey proposing a unified brain-perception-action framework that covers single-agent tasks, multi-agent collaboration, and emergent agent-society behaviours.

1. What Is an Adversarial Agent?

The term adversarial agent sits at the intersection of two converging research threads: adversarial machine learning, which studies how systems can be deliberately misled, and autonomous LLM-based agents, which studies how language models can plan and act over extended horizons. When these threads meet, the result is a system that uses a language model’s reasoning and action capabilities not to assist users, but to probe, deceive, or attack other systems or models.

A key property of LLMs that makes this dual-use tension unavoidable is that the same capability that allows a model to generate persuasive text for a marketing campaign also allows it to generate convincing social-engineering scripts. The same capacity for code generation that accelerates legitimate development can be turned toward writing exploit code. Security researchers consistently observe this dual-use property: a sufficiently capable LLM is simultaneously a potential defender and a potential attacker, depending entirely on how it is directed.

Understanding adversarial agents therefore requires holding two questions in mind at once. First: what can an attacker do to an LLM (poisoning it, jailbreaking it, extracting its weights)? Second: what can an attacker do with an LLM (generating phishing content, automating prompt injection, orchestrating multi-step exploits)? The taxonomy introduced in this lesson spans both directions.

2. Five Attack Categories: Weng’s Taxonomy

Weng’s 2023 survey organises attacks on LLMs into five categories that remain the most widely cited starting point in the field.

Token manipulation alters input tokens to confuse the model’s internal representations. Substituting synonyms, introducing typos, or appending invisible characters are all token-level interventions that can shift a model’s output while leaving the semantic content of the input largely intact to a human reader.

Gradient-based attacks are white-box techniques that exploit the attacker’s access to the model’s internal gradient signals. Because the attacker can compute how the loss changes with respect to each input token, they can optimise adversarial suffixes or prefixes that reliably steer the model toward a target output. This is the most technically demanding category and requires full or partial access to model parameters.

Jailbreak prompting bypasses a model’s safety objectives through clever framing rather than mathematical optimisation. Role-play scenarios, hypothetical framings, and multi-turn manipulation are all jailbreak strategies. Crucially, jailbreaking requires no model access; it operates entirely in the prompt space, making it accessible to any user with API access.

Human red-teaming involves human annotators manually probing a deployed model for failure modes. It is slow and expensive but produces diverse, high-quality failure cases that automated methods often miss. Many of the safety improvements in modern aligned models trace back to human red-teaming data.

Model-based red-teaming replaces human annotators with a separate language model that generates attack prompts automatically. This is the category most directly relevant to “building adversarial agents” and will be explored in depth across Lessons 2 through 6.

3. The Good, the Bad, and the Ugly: A Security Taxonomy

The LLM Security and Privacy Survey (arxiv 2312.02003) introduces an alternative three-category framing that emphasises intent and use-case rather than technique.

The Good covers beneficial security uses of LLMs. Code vulnerability detection is the canonical example: a model fine-tuned on labelled vulnerability data can scan codebases faster than human reviewers and flag patterns that match known exploit classes. Other examples include malware analysis, log anomaly detection, and automated patch generation. These applications treat the LLM as a defensive tool deployed by a security team.

The Bad covers offensive attack uses. Social engineering is the most salient example: LLMs can generate highly personalised phishing emails at scale, dramatically lowering the cost of spear-phishing campaigns. Adversarial prompt construction—crafting inputs designed to manipulate downstream models—also falls here, as does automated generation of disinformation.

The Ugly covers inherent model vulnerabilities that exist regardless of intent. These are properties of the model itself: susceptibility to prompt injection, sensitivity to paraphrased queries, and the possibility of model extraction (recovering approximate model weights through black-box queries). The survey explicitly flags model extraction and safe instruction tuning as underdeveloped areas where the research community lacks robust defences. This is notable because it means that even organisations deploying models defensively cannot yet fully protect their model assets.

The three-category framing is useful for policy and risk discussions, while Weng’s five-category technical taxonomy is more useful for engineering. Both framings will recur throughout this course.

4. The Brain-Perception-Action Framework for LLM Agents

To reason precisely about adversarial agents, it helps to have a clear model of what an LLM-based agent actually is. The LLM Agents Survey (arxiv 2309.07864) proposes a unified brain-perception-action framework that applies to any LLM-based agent, whether benign or adversarial.

The brain is the reasoning and planning core. It decides what goal to pursue, how to decompose that goal into sub-tasks, and which tools or actions to invoke. In a well-aligned agent this module is guided by the operator’s objectives; in an adversarial agent it may be guided by attack objectives such as maximising information leakage or finding a jailbreak path.

The perception module handles multimodal input processing. Modern LLM agents can receive text, images, audio, and structured data. For an adversarial agent, perception is the attack surface on the input side: injecting malicious content into any modality the agent perceives can influence its brain’s subsequent reasoning.

The action module covers tool use and communication: calling APIs, writing files, sending messages, or spawning sub-agents. For an adversarial agent this is the effector side: the mechanism through which attack consequences propagate into the real world. Multi-agent systems introduce additional surface because agents communicate with each other, meaning a compromised agent can propagate malicious instructions downstream through its action outputs.

The survey also covers emergent behaviours in agent societies, including personality drift and social dynamics that arise from agent-to-agent interaction. These emergent properties matter for adversarial settings: a single compromised agent in a multi-agent network may be able to influence the behaviour of neighbouring agents beyond what its direct capabilities would suggest.

5. Access Models, Roles, and the Attacker-Defender Divide

A consistent axis running through every attack taxonomy is access level: how much does the attacker know about the target model?

In a white-box setting the attacker has full access to model weights, architecture, and gradients. Gradient-based attacks live entirely in this quadrant. White-box access is realistic in scenarios involving open-weight models (Llama, Mistral, and similar releases), internal red-team exercises where the security team has full model access, or attacks on fine-tuned derivatives of open models.

In a black-box setting the attacker can only observe outputs given inputs, with no visibility into internals. Jailbreak prompting, model-based red-teaming, and most real-world attacks on commercial APIs operate in this regime. Black-box attacks are generally less technically demanding to mount but harder to defend against systematically, because the defender cannot easily enumerate the input space.

A third regime—grey-box—assumes partial knowledge: perhaps the attacker knows the model family or training procedure but not the exact weights. Transfer attacks exploit this: an adversarial example crafted against an open-weight model sometimes transfers to a closed model from the same family.

The attacker-defender divide also plays out at the system level. Defenses identified in the literature include adversarial training (exposing the model to attack samples during fine-tuning), perplexity filtering (flagging inputs with unusually high token perplexity as potential attacks), and input paraphrasing (transforming inputs before they reach the model to break token-level exploits). Each defence has corresponding circumvention strategies, establishing the adversarial dynamics that this course will explore in detail.

Key Insight: The same five attack categories that apply to attacking an LLM (token manipulation, gradient-based, jailbreak, human red-teaming, model-based red-teaming) also define the toolbox available to an adversarial agent acting against other systems. Understanding the attack surface from the defender’s perspective and the attacker’s perspective simultaneously is what separates a capable security engineer from someone who only knows one side of the field.
Common Misconception: Many learners assume that aligning a model with RLHF or instruction tuning eliminates adversarial vulnerabilities. It does not. The “The Ugly” category in arxiv 2312.02003 specifically identifies model extraction and safe instruction tuning as underdeveloped areas. Alignment reduces the probability of certain harmful outputs under normal conditions but does not close the attack surface for a determined adversary with white-box or persistent black-box access.
